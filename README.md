# 项目统一标准与分工手册

*智慧气象赛道 · 基于 CasCast 的短时强降水临近预报*

## 一、结论与范围

**主数据集统一使用 SEVIR VIL，主模型统一使用 CasCast 官方三阶段流程；CIKM 2017 不再作为主训练集。**

CasCast 的输入和监督目标都是连续的二维雷达图序列，而 CIKM 2017 的原始任务是“15 帧 × 4 高度雷达图 → 中心站点未来累计降水量”。后者只有站点级标量标签，不能直接监督 CasCast 生成未来雷达图；若强行使用，需要另做空间标签构建和模型接口重写，风险高且难以在 10/15 前完成。

本项目的核心交付调整为：根据过去 65 分钟的 VIL 雷达图，生成未来 60 分钟的高分辨率降水回波序列，并重点展示强降水区域的位置、演变和不确定性。若赛题最终要求站点级结果，则在生成的未来雷达图上提取目标站点/邻域的统计量，作为**下游演示**；不把它作为 CasCast 的主训练任务。

## 二、数据集标准

### 2.1 主数据集：SEVIR VIL（唯一必须完成）

| 项目 | 统一标准 |
| --- | --- |
| 数据集 | [SEVIR](https://github.com/MIT-AI-Accelerator/neurips-2020-sevir) 的 VIL（Vertically Integrated Liquid）雷达产品 |
| 与 CasCast 的匹配 | CasCast 官方仓库直接提供 SEVIR VIL 的数据划分、配置、预训练权重和三阶段训练脚本；不改变任务接口即可复现 |
| 单个样本 | 384 × 384 单通道 VIL 图像序列，时间间隔 5 分钟 |
| 输入 / 输出 | 输入前 13 帧（65 分钟），预测后 12 帧（60 分钟） |
| 官方划分 | 训练 35,718；验证 9,060；测试 12,159 个样本，使用 CasCast 仓库 `sevir_list` 中的划分，禁止自行随机打乱 |
| 原始存储 | 下载的 SEVIR `.h5` 原文件只存本机或共享数据盘；仓库仅保留下载说明、样本列表、预处理代码和小型检查样本 |
| 预处理产物 | `pixel_data/sevir/{train_2h,val_2h,test_2h}` 下的 `.npy` 样本；格式、归一化和样本命名严格对齐官方脚本 |

下载入口和训练说明以 [CasCast 官方仓库](https://github.com/OpenEarthLab/CasCast) 为准。开始训练前，队员①必须随机抽查 10 个样本：形状为 `(25, 384, 384)`（或项目读取器等价的通道维顺序）、无 NaN/Inf、时间顺序正确，并把检查结果记录到 `docs/data_check.md`。

### 2.2 非主数据集的处理

| 数据集 | 决策 | 使用边界 |
| --- | --- | --- |
| CIKM 2017 | 不作为 CasCast 主训练集 | 仅在有明确站点级展示需求、且主线已跑通后，做“由预测图提取站点邻域特征”的小规模演示；不用于主榜单或主结论 |
| HKO-7 | 暂不使用 | CasCast 论文使用过，但获取通常需要申请；不把进度押在数据审批上 |
| MeteoNet | 暂不使用 | 可作为论文中的外部泛化展望；截止日前不扩展第二套预处理链路 |

**数据集冻结规则：** 9/30 后除修复数据错误外，不新增数据集、不更换主数据划分。任何跨数据集结果必须显著标注为“非同一数据协议”，不得与 SEVIR 主实验直接比较。

## 三、任务定义

给定过去 13 帧、每帧间隔 5 分钟的 SEVIR VIL 雷达图，预测未来 12 帧 VIL 雷达图。主评估对象是未来 0–60 分钟每一帧的空间降水回波；强降水评估单独按阈值分档，避免平均误差掩盖极端区域的漏报。

如需要站点级展示，固定站点坐标和邻域窗口，在所有预测帧上提取 VIL 均值、最大值、强回波面积等指标；这一步属于**推理后处理**，不得反向改写 SEVIR 主实验的标签或划分。

## 四、模型标准

### 4.1 CasCast 主线（必须遵守的三阶段顺序）

| 阶段 | 模块 | 输入 → 输出 | 完成标准 |
| --- | --- | --- | --- |
| 0 | 官方推理复现 | 官方预训练模型 + 官方预处理样本 → 12 帧预测 | 能稳定生成样例、保存输入/真值/预测可视化；这是最低可交付版本 |
| 1 | 确定性部分 | 历史 VIL → 未来 VIL 的粗预测（官方 EarthFormer 配置） | 验证集指标和检查点可复现 |
| 2 | 自编码器 | 真值与确定性预测 → 潜变量 | 重建图可用，且潜变量文件与样本 ID 一一对应 |
| 3 | 概率部分 CasFormer | 压缩后的真值 + 确定性预测条件 → 多样本未来预测 | 固定随机种子生成多成员预测，输出均值与不确定性图 |

阶段 0 是提交保底，阶段 1 是最低训练成果；只有阶段 1 稳定后再进入阶段 2 和 3。**禁止并行从零重写 CasCast 或以 3D-CNN/ConvLSTM 取代主模型。**它们可以在资源允许时作为轻量对比基线，但不得阻塞主线。

### 4.2 创新点（聚焦、可消融）

核心创新保持为“强降水感知训练”，但实现位置调整到与 CasCast 兼容的确定性阶段损失：

`L = L_base + λ · w(y) · L_tail`

- `L_base`：CasCast 官方确定性阶段的基础重建损失；
- `w(y)`：按 VIL 强度分桶或连续函数给高强度像素更高权重；
- `L_tail`：仅对高强度区域计算的重建/结构损失；
- `λ`、阈值和权重只能由验证集选择，测试集只在方案冻结后评一次。

先完成“官方损失”与“官方损失 + 强降水感知项”的单变量消融；不要同时叠加 focal、EVL、注意力模块等多个改动，以免无法归因。

## 五、评价指标与实验规范

| 类别 | 统一指标 | 报告方式 |
| --- | --- | --- |
| 总体误差 | MSE / MAE（与官方实现口径一致） | 按未来 lead time 和全时段均值报告 |
| 降水命中 | 各官方 VIL 阈值下的 CSI、POD、FAR | 单列最高强度阈值；不能只报平均值 |
| 空间质量 | SSIM 或官方已实现的图像质量指标 | 展示典型个例，不作为唯一结论 |
| 概率质量 | 多样本预测的均值、标准差/分位数图；可行时增加 CRPS | 明确样本数和随机种子 |
| 消融 | 官方 CasCast vs + 强降水感知项 | 同一数据划分、训练轮数、种子和评测脚本 |

所有实验必须写入 `experiments/<run_name>/config.yaml`、`metrics.json` 和 `seed.txt`。测试集不可用于选阈值、选 epoch、选权重或挑选展示样例。

## 六、开发环境标准

| 项目 | 统一标准 |
| --- | --- |
| Python / PyTorch | 优先对齐 CasCast 官方环境：Python 3.9.17、PyTorch 2.0.1 + CUDA 11.8；如迁移版本，需记录兼容性结果 |
| 分布式训练 | 先单卡/小样本跑通；只有流程正确后才使用 DDP/SLURM 脚本 |
| 关键依赖 | 以官方 `requirements` / 环境文件为准，另使用 numpy、h5py、matplotlib、tensorboard 或 wandb |
| 随机性 | 固定并记录 Python、NumPy、PyTorch 与数据加载器随机种子；概率推理额外记录采样种子和样本数 |
| 资源策略 | 先用官方预训练推理和小规模训练验证链路，再启动完整训练；每个阶段保留可恢复检查点 |

## 七、分工与接口

三人的职责按 CasCast 数据流切分，交接物必须可独立验收，避免“所有人都在调参、没人能复现”。

### 7.1 学长（技术负责人：集成、创新与质量门）

- 冻结任务协议：SEVIR 划分、阈值口径、主指标、提交图表模板。
- 负责 CasCast 代码集成、官方预训练推理复现（阶段 0）及阶段 3 CasFormer 的启动/采样；处理接口错误和算力调度。
- 定义强降水感知损失的唯一候选公式、超参数搜索范围和消融表；审核是否出现测试集泄漏。
- 每日合并结果，批准“进入下一阶段”或“回退到保底版本”的决策；负责技术路线、创新性和 AI 技术章节终审。

**交付物：** `configs/`、可运行推理命令、阶段 3 检查点/采样脚本、消融结论、最终技术审校意见。

### 7.2 队员①（数据负责人：SEVIR、预处理、评测）

- 下载并核验 SEVIR VIL，依据官方 `sevir_list` 完成 `.h5 → .npy` 预处理，维护数据版本和校验日志。
- 维护数据加载器、训练/验证/测试隔离、样本 ID 映射和可视化抽检；任何数据异常先修复再交给训练。
- 实现/核对统一评价脚本：按 lead time 的 MSE/MAE、各阈值 CSI/POD/FAR、样例导出。
- 为阶段 1、2、3 生成所需索引和数据一致性报告；不负责改变模型结构。

**交付物：** `data/README.md`、`docs/data_check.md`、预处理命令、固定评测命令、`metrics.json` 与图表数据。

### 7.3 队员②（训练与材料负责人：确定性阶段、自编码器、表达）

- 训练并复现确定性 EarthFormer（阶段 1），记录基线配置、日志、最佳验证检查点和失败案例。
- 在学长确认阶段 1 后，训练自编码器（阶段 2）并运行真值/确定性预测的潜变量压缩；对齐样本 ID 后交付给学长。
- 依据统一评测结果制作对比表、消融表、逐 lead time 曲线、强降水案例图和不确定性示意图。
- 撰写作品方案、PPT 和演示视频；所有数字只能引用已冻结的 `metrics.json`，由学长审校后定稿。

**交付物：** 阶段 1/2 检查点、潜变量目录及索引、图表源文件、作品方案/PPT/演示视频初稿。

### 7.4 交接与验收规则

| 交接 | 验收人 | 必须通过的检查 |
| --- | --- | --- |
| 队员① → 队员② | 队员② + 学长 | 固定样本能读取；形状、时间顺序、样本 ID 与清单一致；评测脚本能运行 |
| 队员②阶段 1/2 → 学长 | 学长 | 验证指标、配置、种子、检查点路径齐全；潜变量与原样本一一对应 |
| 学长阶段 3 → 队员①② | 队员① + 队员② | 固定种子可重生成；预测、均值、不确定性图与指标可由脚本得到 |
| 全员 → 提交 | 学长 | 文档数字、图表、配置、检查点和演示视频版本一致 |

- 代码仓库统一按 `data/`、`configs/`、`models/`、`scripts/`、`experiments/`、`eval/`、`docs/` 分目录；大文件和数据不提交 Git。

- 每次共享结果至少附：Git commit、配置文件、数据版本、检查点、验证指标、评测命令和随机种子。
- 网盘命名（官方要求）：`参赛团队编号-智慧气象-作品名称-XX（材料名称）`。
- 所有材料不得出现学校名称与指导教师姓名。
